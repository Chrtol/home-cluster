# Phase 20.5 Plan 01: Responsibility Assignment Foundation Summary

**One-liner:** Database models and CRUD API for assigning care responsibility at reptile-level and schedule-level to support multi-user household workflows.

## Overview

Created the foundational infrastructure for responsibility assignment in multi-user households. This enables users to assign care responsibility for specific reptiles or individual schedules to one or more household members. Unassigned reptiles remain accessible to all household members (default shared responsibility).

**Purpose:** Foundation for user-level streak calculation and gamification features in subsequent plans.

## Implementation Details

### Database Models

**ReptileResponsibility:**
- Junction table: `reptile_id` + `user_id` (unique constraint)
- Metadata: `assigned_at`, `assigned_by_user_id`
- CASCADE delete on reptile/user removal
- Supports shared responsibility (multiple users per reptile)

**ScheduleResponsibility:**
- Junction table: `schedule_id` + `user_id` (unique constraint)
- Metadata: `assigned_at`, `assigned_by_user_id`
- CASCADE delete on schedule/user removal
- Overrides reptile-level assignments for specific schedules

### API Endpoints

**Reptile-level (8 endpoints total):**
1. `GET /api/responsibilities/reptiles/{reptile_id}` - Get assignments
2. `PUT /api/responsibilities/reptiles/{reptile_id}` - Update assignments (replaces all)
3. `DELETE /api/responsibilities/reptiles/{reptile_id}` - Clear assignments (everyone responsible)
4. `DELETE /api/responsibilities/reptiles/{reptile_id}/users/{user_id}` - Self-remove from shared responsibility

**Schedule-level:**
5. `GET /api/responsibilities/schedules/{schedule_id}` - Get assignments
6. `PUT /api/responsibilities/schedules/{schedule_id}` - Update assignments (replaces all)
7. `DELETE /api/responsibilities/schedules/{schedule_id}` - Clear assignments (inherit from reptile)

**Household overview:**
8. `GET /api/responsibilities/overview` - Get all assignments with `is_single_user` flag

### Permission Model

- All endpoints require household membership verification
- Assignment updates validate all user_ids are household members
- Self-removal endpoint enforces `current_user.id == user_id`
- No specific access level required (all household members can manage responsibilities)

## Schemas Added

1. `ResponsibilityAssignment` - Individual assignment with user_id, timestamps, attribution
2. `ReptileResponsibilityResponse` - Assignments + `is_unassigned` flag
3. `ScheduleResponsibilityResponse` - Assignments + `inherits_from_reptile` flag
4. `ResponsibilityUpdate` - Request schema with `user_ids` list (replaces all)
5. `HouseholdResponsibilityOverview` - Household summary with `is_single_user` detection

## Notes

**Single-user detection:** The `is_single_user` flag in `/overview` endpoint enables conditional UI rendering - responsibility assignment UI should be hidden in single-user households.

**Shared responsibility semantics:** Multiple users can be co-responsible. When no users assigned, reptile is implicitly shared by all household members (default behavior).

**Schedule override behavior:** Schedule-level assignments take precedence over reptile-level assignments. Clearing schedule assignments makes it inherit from reptile.

**Self-removal safety:** Users can remove themselves from shared responsibility at any time. This prevents scenarios where users feel "trapped" in assignments they didn't consent to.
